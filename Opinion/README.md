# Opinion フォルダ運用ルール

本プロジェクトは複数の AI (Claude / Codex / Gemini) で意見を出し合って改善する。
このフォルダは AI 同士の意見表明を集約する場所。

---

## 役割と書込み権限

| AI | 意見ファイル | プロジェクトファイル編集 | 参加形態 |
|---|---|---|---|
| Claude | `ClaudeFeedback.md` | 編集可 | 常任 (実装本体) |
| Codex | `CodexOpinion.md` | 編集不可 (Opinion/ のみ可) | 常任 (分析・検証・代替案立案) |
| Gemini | `GeminiOpinion.md` | 編集不可 (Opinion/ のみ可) | **スポット** (大局観・第三者レビュー) |

すべての AI とも本フォルダ内 (`Opinion/`) には自由にサブフォルダ・検討用ファイルを追加してよい。

### Gemini はスポット参加
「決めるために呼ぶ」のではなく「決める前に大きな穴がないか見るために呼ぶ」位置づけ。
詳細は `GEMINI.md` 参照。

---

## いつ書く・いつ読む

**書く / 読むのはユーザーの指示があった時だけ。**

- ユーザーが「Codex に意見を聞きたい」「Claude の見解確認」等と明示した時のみ
- 自発的に書きにいくのは「○○について意見を書いて」と依頼された場合
- 通常タスク (バグ修正、コード編集、運用) では意見ファイルを参照しなくてよい

---

## ファイル構造

`ClaudeFeedback.md` / `CodexOpinion.md` / `GeminiOpinion.md` は
**追記式の running file**。最新を上、古いログを下に流す:

```markdown
## 2026-05-12: トピック名
(本文)
---
## 2026-05-11: 別の論点
```

検討中で散らかしたい場合は `Opinion/<topic>/` にサブフォルダを切る。

---

## サブフォルダ慣行

| フォルダ | 用途 |
|---|---|
| `codex_briefs/` | Claude → Codex への依頼書 (`YYYY-MM-DD_topic.md`) |
| `gemini_briefs/` | Claude → Gemini への依頼書 (同上) |
| `Opinion/<topic>/` | 横断調査・監査用 (例: `odds_features/`, `ml_audit/`) |

---

## 書き方のスタンス

- 相手の意見は尊重する。ただし**忖度せず**自分の意思表示や提案は積極的に。
- 数値・ロジックには根拠 (ファイル名:行番号 / CSV出典 / commit hash) を添える。
- 反対意見も歓迎。ただし「なぜそう考えるか」を必ず併記する。
- ユーザーが最終判断者。AI 同士で結論を出さなくてよい。
